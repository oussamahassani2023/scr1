# Лабораторная работа № 2 — SCR1
## Вариант 10: обработка исключения Breakpoint

### 1. Цель работы

Настроить тестовое окружение процессорного ядра SCR1 и проверить обработку исключения Breakpoint с использованием теста `isa/rv32mi/sbreak.S`.

Параметры варианта:

- **Тест:** `isa/rv32mi/sbreak.S`
- **Reset Vector:** `0x400`
- **Trap Vector:** `0xA00`
- **Ожидаемое сообщение:** `breakbreak`

### 2. Выполненные изменения

Для настройки проекта были изменены следующие файлы:

- `src/includes/scr1_arch_description.svh` — заданы адреса векторов сброса и обработки исключений.
- `sim/tests/common/link.ld` — изменена компоновка тестовой программы с учётом заданных адресов.
- `sim/tests/common/riscv_macros.h` — изменены макросы тестовой инфраструктуры и добавлена логика обработки исключения Breakpoint.
- `sim/tests/riscv_isa/rv32_tests.inc` — список тестов ограничен тестом `isa/rv32mi/sbreak.S`.
- `src/tb/scr1_top_tb_ahb.sv` — обновлены адреса в тестовом окружении AHB.
- `src/tb/scr1_top_tb_axi.sv` — обновлены адреса в тестовом окружении AXI.

В обработчик исключений была добавлена проверка причины исключения Breakpoint и логика вывода сообщения `breakbreak`.

### 3. Сборка и запуск теста

Для сборки и запуска использовалась команда:

```bash
make run_verilator TARGETS=riscv_isa
```

Сборка проекта с использованием Verilator завершилась успешно.

Однако при моделировании тест завершился по тайм-ауту. В выводе тестового окружения было получено сообщение:

```text
Error: TIMEOUT sbreak.hex

Summary: 0/1 tests passed
```

Таким образом, успешное прохождение теста не подтверждено.

### 4. Ход диагностики и попытки устранения ошибки

После обнаружения тайм-аута были выполнены дополнительные проверки.

**4.1. Проверка базовой конфигурации**

До внесения изменений исходный проект был запущен с помощью Verilator. В базовой конфигурации все 56 тестов прошли успешно, включая `sbreak`. Это подтвердило, что исходная конфигурация поддерживает выполнение данного теста.

**4.2. Проверка адресов векторов**

Для варианта 10 были заданы адрес сброса `0x400` и адрес вектора обработки исключений `0xA00`. Изменения внесены в описание архитектуры, linker script и тестовые окружения AHB и AXI.

**4.3. Ограничение списка тестов**

В `sim/tests/riscv_isa/rv32_tests.inc` был оставлен только тест `isa/rv32mi/sbreak.S`, чтобы сосредоточить проверку на обработке исключения Breakpoint.

**4.4. Проверка макросов и обработчика исключений**

Были изучены и изменены макросы тестовой инфраструктуры в `sim/tests/common/riscv_macros.h`. В обработчик добавлена проверка причины исключения Breakpoint и логика вывода ожидаемого сообщения.

**4.5. Повторная сборка и анализ результата**

После изменений проект успешно собрался. При запуске тест завершился по тайм-ауту с результатом `0/1 tests passed`. Следовательно, исправить проблему на данном этапе не удалось.

**4.6. Проверка выходных файлов**

В каталоге сборки были обнаружены файлы `sbreak.elf`, `sbreak.hex`, `sbreak.dump`, `test_results.txt` и `sim_results.txt`. Они позволяют сохранить результаты сборки и зафиксировать результат моделирования.

**4.7. Проверка трассировки**

Файлы `trace_mprf_diff_.log` и `trace_csr_.log` среди полученных результатов не обнаружены. Используемая конфигурация сборки содержит параметр `TRACE=0`. Поэтому наличие требуемых файлов трассировки не подтверждено.

### 5. Результаты и ограничения

В ходе работы была подготовлена конфигурация для варианта 10, изменены адреса векторов и обработчик исключений, а также настроен список запускаемых тестов.

При этом остаются нерешёнными следующие вопросы:

- причина тайм-аута при выполнении `sbreak.S`;
- корректность перехода к обработчику исключения по адресу `0xA00`;
- вывод сообщения `breakbreak` во время симуляции;
- корректное завершение теста;
- получение файлов трассировки регистров и CSR.

Успешная сборка не означает успешного прохождения теста. На текущем этапе результат моделирования отрицательный.

### 6. Вывод

В рамках лабораторной работы были изучены настройки тестового окружения SCR1, изменены параметры векторов сброса и обработки исключений, а также внесены изменения в макросы обработки исключений.

Базовая конфигурация успешно прошла 56 тестов из 56, включая `sbreak`. После внесения изменений сборка также завершилась успешно, однако целевой тест `sbreak.S` завершился по тайм-ауту.

Таким образом, основные настройки варианта 10 подготовлены, но корректность обработки Breakpoint пока не подтверждена. Для завершения работы необходимо продолжить диагностику обработчика исключений, вывода сообщения и механизма завершения симуляции.
